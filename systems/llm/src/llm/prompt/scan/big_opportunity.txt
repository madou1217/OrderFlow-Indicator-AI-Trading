FLOW FIELD SEMANTICS

Interpret flow families by their market function in the current auction.

- `delta_read` is derived from the timeframe's latest closed bar delta split between futures and spot.
- Current partial-window footprint delta does not replace `delta_read`; it matters only if it materially diverges, and then it should appear in `evidence_trace.conflicting_facts`.
- `cvd_read` is derived from the timeframe CVD slope and whether it supports, lags, or opposes price.
- `whale_read` is derived from whale delta or whale notional for the current timeframe, and from whether spot and futures whale activity align or diverge on that timeframe.
- `orderbook_read` is derived from orderbook and near-price execution constraints such as OBI, OFI, depth imbalance, stacked imbalance, liquidity walls, and other near-price resting pressure.

Complete all four flow families from the input fields that express those market functions.
Map each family into the schema by what it says about the current auction.

ACTIVE NOW VS BACKGROUND

Your primary task is to describe what is still active now in the market.

Treat current price location, current value state, active range, current flow, current participant behavior, and the most recent still-relevant closed bars as the primary active-now evidence.

Treat older events, older path history, and supporting context as background evidence.

Use background evidence to explain the active market state and active participant tasks.
The active-now layer defines the read; the background layer explains how that read developed.

- current price location

Prior continuation, acceptance, or defense belongs in the active read only when it still remains part of the current organizing state.

`combined_flow_state` is relative to `state_parse.control_read.side`:
